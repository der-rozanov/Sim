## Побочная разработка (ради интереса, вне основной линии)

### Пилотажный комплекс C-11 в автономном режиме (идея 2026-10-27)

САУ сама выполняет комплекс фигур по схеме C-11 (Starting Schedule C-11, январь 2010).
Приоритет ниже основных блоков; делать, когда будет время.

**Фигуры** (опознаны по схеме на глаз; уточнить по описанию C-11, если оно найдётся):
1 — петля; 2 — поворот на вертикали; 3 — квадратная петля; 4 — полубочка на восходящей
линии под 45° и выход полупетлёй; 5 — бочка; 6 — горка: вертикаль вверх, полупетля,
вертикаль вниз с полубочкой; 7 — кубинская восьмёрка; 8 — полупетля с полубочкой;
~~9 — штопор~~ — **не делаем** (решение автора 2026-10-27): срыв в Cm и боковые
производные после срыва не моделируются, нет данных.

**Что мешает сейчас:**
- ~~Углы Эйлера в физике вырождаются при θ = ±90°~~ — решено: кватернион в состоянии
  (РЕШ-35, 2026-10-27).
- САУ (режимы PITCH/ALTITUDE/ROUTE, TECS, курс через φ_ref) рассчитана на полёт около
  горизонта. Годятся внутренние контуры по p и q.
- Поворот на вертикали (фигура 2): при Va → 0 РН работает за счёт обдувки винтом, а её
  в модели нет. Варианты — заменить горкой с разворотом (wingover) либо добавить модель
  обдувки (данные винта APC 11×7E есть).

**Подход (набросок):** новый режим САУ `Mode.AEROBATIC` с секвенсором фигур. Каждая
фигура — аналитическая траектория как функция длины дуги (прямая, дуга радиуса R,
вращение по крену) → уставка ориентации кватернионом вдоль касательной + программа
крена → ошибка ориентации → уставки p, q, r для существующих контуров; газ — по энергии.
Ориентир — скриптовая аэробатика ArduPilot (`plane_aerobatics.lua`). Сначала истинные
датчики, потом реалистичные + EKF.

**Состояние (2026-10-27):** А, Б, В сделаны — комплекс 1–8 летает в s11 (горка с
разворотом вместо поворота на вертикали — решение автора); режим `Mode.AEROBATIC` в `SAU`,
клавиша `K` в 3D-тренажёре, полёт на реалистичных датчиках + EKF (β = 0 в пилотаже
выключено, ветер — на входе). Дальше по желанию: ограничение перегрузки; точность в
турбулентности на EKF (9–22 м против 4 м на истине — порывы без измерения α, β).

**Порядок:** (А) ориентация в физике — блок 1 основной линии ✅; (Б) регулятор
`control/aerobatics.py` и фигуры по одной (петля, бочка, квадратная петля) ✅ 2026-10-27,
docs/control.md, раздел 13, `checks/check_aerobatics.py`: ошибки по радиусу и направлению
прямых, потеря высоты, max перегрузка и α; (В) секвенсор, `scenarios/s11_aerobatics.py`,
`.flightlog`, просмотр в viewer3d, панель вертикальной плоскости в `viz/viewer.py` ✅ 2026-10-27.

**Ожидания по ЛА** (оценка, FPV 1.8 м): T/W = 1.25 и Va_max ≈ 31 м/с хватает для
вертикалей; петля на 25 м/с при n ≈ 4 — R ≈ V²/(g·(n − 1)) ≈ 21 м. Слабое место — бочка:
у высокоплана мала боковая сила фюзеляжа на ноже, вероятна потеря высоты.

## Известные дефекты и долги

- `compute_trim` — линейный по CL/Cm (без sigmoid), только горизонтальный полёт;
  боковой трим (δa против момента винта) не считает.
- Срыв в Cm и боковые производные после срыва не моделируются (нет данных).
- `Log.E_kin` считается по скорости без ветра: при ветре это энергия по земной скорости.
- `control/lqr.py` использует scipy (DARE) — исключение из правила «только numpy».
- Мощность в логах — полезная мощность винта T·Va; электрическая потребует, чтобы
  `propeller()` возвращал обороты.
- Числа в docs/scenarios_report.md сняты на прежнем ЛА.
- EKF не убирает уход GPS-положения (5–8 м, не наблюдаем) и до первого манёвра может
  ошибаться по ориентации до ~2° вдоль вектора магнитного поля (docs/control.md, 9.3).
- EKF самоуверен по положению (найдено вкладкой ESTIMATOR, 2026-10-17; моделирование: FPV,
  16 м/с, ветер 5 м/с, слабая турбулентность, 100 с): σ положения 0.2 м при ошибке
  относительно истины 15 м. Причина — уход GPS не входит в модель фильтра, а R положения
  (2 м)² много больше белого шума отсчёта (0.2 м): NIS GPS-положения ≈ 0.06. Варианты — две
  составляющие ухода GPS в состоянии (марковский процесс; рекомендация) или шум процесса по
  положению. Решение — за автором. Там же: уход GPS 16 м против 5–8 м в docs — перепроверить
  модель ухода (`GaussMarkov`, `gps_pos_drift_sigma`).
- Контур РН — ПИ по β зонда через фильтр НЧ τ_β = 0.1 с (РЕШ-33, временно). Фильтр убирает
  дребезг δr (ход за 50 с в штиль 1600° → 115°, моделирование), но запаздывает: |β|max в
  разворотах s8 2.92° → 3.32°. Сделать: демпфер рыскания по r (с ФВЧ), упреждение
  r_ref = g·sin φ/Va и контур по боковому ускорению a_y (ArduPilot `YAW2SRV_SLIP`) — без
  датчика β, как на серийных ЛА; β зонда — только для тематики зонда.
- Синтетическое β = 0 почти не используется: NIS ≈ 0.01 при σ = 0.3 рад (умолчание
  EKF2_BETA_NOISE); продольная к полёту составляющая ветра — σ ≈ 0.9 м/с.

# 3D-тренажёр (`viz/viewer3d.py`)

3D-проигрыватель полётных логов `.flightlog` на движке Ursina (Panda3D).
Решение о зависимости — РЕШ-16 (`docs/decisions.md`). Модуль только отображает:
физику и САУ не импортирует, читает файл через `flight_logger.load_log()`.

Статус (2026-10-06): блок 1 — проигрывание логов ✅; блок 2 — пилотирование
в реальном времени `scenarios/GameScenario3D.py` ✅ (раздел 8).

---

## 1. Установка и запуск

```bash
pip install ursina                       # один раз; тянет panda3d

python viz/viewer3d.py                   # последний .flightlog из results/
python viz/viewer3d.py results/<файл>.flightlog
python viz/viewer3d.py <файл> --speed 2 --cam 3 --at 20
python viz/viewer3d.py <файл> --at 22 --cam 1 --shot out.png   # скриншот и выход
```

| Ключ | Назначение |
|---|---|
| `path` | файл `.flightlog`; без него — самый свежий в `results/` |
| `--speed` | скорость проигрывания (по умолчанию 1 — реальное время) |
| `--cam 1..4` | камера на старте |
| `--at T` | начать с момента T, с |
| `--shot файл.png` | отрисовать ~40 кадров, сохранить скриншот, выйти (для отчётов и проверок) |

Из кода: `from viz.viewer3d import play; play(path, speed=1.0, cam=1)`.

Лог создаётся любым сценарием, который вызывает `FlightLogger.save()`
(s1–s13). `GameScenario.py` лог пока не пишет.

## 3. Что на экране

**Сцена**
- Рельеф: поля 160×160 м, холмы ±12 м, лес, гряда гор по краю карты
  (ориентир горизонта), ВПП 600×30 м в точке старта вдоль начального курса.
  Генерируется процедурно (seed = 7), освещение «запечено» в цвета вершин.
  Размер карты — габарит траектории + 3 км с каждой стороны.
- Небо, дымка (линейный туман, в обзоре реже).
- Красный след — пройденный путь; тёмная линия на земле — его проекция;
  белый отвес — от ЛА до земли.

**Силуэт ЛА** — масштаб по размаху `b` и хорде `c` из метаданных лога
(фюзеляж 0.7·b). Рули отклоняются по логу на истинные углы:

| Руль | Знак (как в `sim/config.py`) |
|---|---|
| δe > 0 | задняя кромка руля высоты вниз (нос вниз, `Cmde < 0`) |
| δa > 0 | правый элерон вверх, левый вниз (правый крен, `Croll_da > 0`) |
| δr > 0 | задняя кромка руля направления влево (нос влево, `Cn_dr < 0`) |

Винт вращается пропорционально δt.

**Приборная панель**: t и скорость проигрывания; Va, h; α, β; φ, θ; ψ и путевой
угол χ (по земной скорости, из производных x, y); δe, δa, δr, δt; ветер
(С, В, верт.); индикатор УА НОРМ / ПРЕД / КРИТ / СРЫВ (канал `alert` лога);
последнее событие из `meta["events"]`. На полосе времени — метки событий.

## 4. Системы координат и ориентация

Симулятор (docs/physics.md): земная СК — x на север, y на восток, h вверх
(D = −h); связанная СК — x вперёд, y на правое крыло, z вниз; углы φ, θ, ψ,
порядок поворотов ZYX.

Ursina — левая СК: X вправо, Y вверх, Z вперёд. Отображение:

```
(N, E, D)  ->  (X, Y, Z) = (E, −D, N)
```

При нём восток справа от севера, как на карте, — разворот вправо (ψ растёт)
и на экране идёт вправо, зеркальности нет.

Ориентация силуэта задаётся не углами Эйлера Ursina, а двумя векторами из
матрицы R_b→n = Rz(ψ)·Ry(θ)·Rx(φ):

```
нос  x_b = [cθ·cψ,  cθ·sψ,  −sθ]                       (1-й столбец)
низ  z_b = [cφ·sθ·cψ + sφ·sψ,  cφ·sθ·sψ − sφ·cψ,  cφ·cθ] (3-й столбец)
верх = −z_b
```

Оба переводятся в СК Ursina и передаются в Panda3D `lookAt(нос, верх)`.
Так исключена путаница порядка поворотов и знаков углов движка.

Положение интерполируется линейно между отсчётами лога (плавность на 60+ кадр/с);
углы и рули берутся по ближайшему отсчёту (при dt = 0.01 с этого достаточно).

## 6. Устройство кода

| Элемент | Назначение |
|---|---|
| `ned_to_u()`, `body_axes()` | чистый numpy: перевод СК, оси связанной СК |

| `View3D` | всё вокруг ЛА: силуэт, след и тень, отвес, 4 камеры, приборная панель; источник состояния — снаружи (`render()`, `set_hud()`) |

САУ не импортирует (правило 5 CLAUDE.md: `viz/` не знает `control/`).

## 7. Ограничения

- Рельеф декоративный: в физике его нет. В проигрывателе ЛА может пролететь
  «сквозь» холм; в игре касание поверхности останавливает полёт (только логика игры).
- Местность одна и та же для всех логов (фиксированный seed), центрируется по
  траектории.
- Вектор воздушной скорости не рисуется — α и β видны только по приборам и по
  расхождению носа со следом (стрелка потока — возможное улучшение).
- Второй агент парного прогона (`paired`, s9) не отображается.
- Ursina — только в `viz/viewer3d.py`; остальной проект по-прежнему numpy + matplotlib.

## 8. Пилотирование в реальном времени (`scenarios/GameScenario3D.py`)

```bash
python scenarios/GameScenario3D.py                          # штиль, h0 = 100 м
python scenarios/GameScenario3D.py --wind-n -5 --wind-e 3   # ветер на север / восток, м/с
python scenarios/GameScenario3D.py --ap --cam 3 --h0 200    # старт с САУ, камера, высота
```

Физика — та же 6DOF-модель: `step_rk4`, dt = 0.01 с, управление заморожено на шаг.
В каждом кадре выполняется столько шагов, сколько прошло реального времени
(не больше 10 за кадр — при просадке кадров игра замедляется, а не «прыгает»).
Старт — балансировочный горизонтальный полёт на север, Va = 30 м/с, над ВПП.

**Ручной режим** — рули отклоняются, пока клавиша нажата, и возвращаются к
балансировке со скоростью 20°/с (как ручка RC-пульта):

| Клавиша | Действие | Отклонение |
|---|---|---|
| W / S | руль высоты: нос вниз / вверх | δe = δe_трим ± 2° |
| A / D | элероны: крен влево / вправо | δa = ∓3° / ±3° |
| Q / E | руль направления: нос влево / вправо | δr = +3° / −3° |
| ↑ / ↓ | триммер руля высоты (↑ — нос вниз) | ±0.3° за нажатие |
| X / Z | тяга | ±5 % за нажатие |

Отклонения подобраны по отклику модели в разомкнутом контуре (Va = 30 м/с,
1 с удержания): δa 3° → p ≈ 37°/с, φ ≈ 32°; δe 2° → q ≈ 8°/с; δr 3° → r ≈ 9°/с.
Для сравнения: δa 10° даёт φ ≈ 90° за 1 с — неуправляемо.

**САУ** (P — вкл/выкл; при включении захватываются текущие θ, Va, путевой угол χ):

| Клавиша | Действие |
|---|---|
| W / S | θ_ref ∓1° (в режиме H — h_ref ∓10 м) |
| A / D | χ_ref ∓10° |
| X / Z | Va_ref ±1 м/с |
| H | удержание высоты (захват текущей; закон θ_ref = α_трим + KH·(h_ref − h)) |

Продольный канал — `PitchController` + `SpeedController` (как в GameScenario),
боковой — `LateralController` (как в s12/s13: χ → φ_ref → δa, β → δr).
Измерения в САУ истинные, без шума (как в исходном GameScenario).

Общие клавиши: Пробел — пауза, R — сброс, 1–4 — камера, M — масштаб, Esc — выход.
Касание поверхности — «СТОЛКНОВЕНИЕ», полёт останавливается (R — сброс).

**Запись**: каждый полёт (до R или до выхода) сохраняется отдельным файлом
`results/Sim_Игра_3D_*.flightlog` (если длился > 2 с) с событиями «САУ вкл/выкл»,
«удержание h», «столкновение»; время в каждом файле начинается с 0 и монотонно.
Два сохранения в одну секунду не затирают друг друга (суффикс `_2`, `_3`, … —
`flight_logger._auto_path`). Пересмотр — `python viz/viewer3d.py`.
Крен на приборной панели приводится к [−180°, 180°) (при бочках φ в состоянии копится).

**Местность**: периодическая (квадрат 5 км, сетка 3×3), переставляется под ЛА
на целое число периодов — летать можно бесконечно, шва нет
(|h(X+P, Z) − h(X, Z)| ~ 1e−13 м). Гор по краю нет.

**Проверено (2026-10-06, программные нажатия клавиш)**:

| Действие | Результат |
|---|---|
| без нажатий 1 с | φ = 0, h = 100.0 — баланс |
| D 1 с, затем A 1 с | φ = +29° → +13° → ≈ 4° |
| S 1 с | h 97.6 → 107.8 м за 3 с, Va 29.6 → 28.2 |
| САУ, χ_ref +90° | χ 21° → 111° за < 10 с, φ → 0 |
| то же, боковой ветер 5 м/с на восток | χ = 113.3° (удержан), ψ = 117.4° (снос в ветер), β ≈ 0 |
| удержание h, h_ref +50 м | 154 → 202.8 м за 20 с (статическая ошибка П-закона ~1–2 м) |
| производительность | 71–75 кадр/с, симуляция/реальное время = 1.00 |

**Ограничения**:
- При включении САУ ЛА проседает на 5–10 м — известный дефект `PitchController`
  (нет упреждающего δe_trim, CLAUDE.md «Открытые дефекты»).
- САУ рассчитана на Va ≈ 30 м/с; вне 20–35 м/с качество падает (gain scheduling частичный).
- Шум датчиков и ветер с порывами в игре не включены (ветер — только постоянный).

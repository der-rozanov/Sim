## 2. Архитектура управления

### demo_control.py — контур тангажа

```
Уставка тангажа
theta_ref ──────────────────────────────────────────────┐
                                                        │
                                            ┌───────────▼────────────┐
                   Гироскоп (q_meas) ──────►│   Внешний ПИД тангажа │
                   ИНС-тета (theta_meas) ──►│   theta: Kp=1.5 Ki=0.1│──► q_ref
                                            └────────────────────────┘
                                                        │
                                            ┌───────────▼────────────┐
                   Гироскоп (q_meas) ──────►│  Внутренний ПИД q     │
                                            │  q:     Kp=0.5 Ki=0.05│──► delta_e_cmd
                                            └────────────────────────┘
                                                        │
                                            ┌───────────▼────────────┐
                                            │  Насыщение ±25°        │──► delta_e
                                            └────────────────────────┘

throttle = trim_throttle = const   (в демо газ фиксирован)
```

**Почему два контура, а не один?**  
Прямой ПИД theta → delta_e реагирует на отклонение тангажа, но не знает, с какой угловой скоростью ЛА уже вращается. Если q_meas уже = q_ref — ПИД продолжает добавлять отклонение руля. Внутренний q-контур останавливает нарастание прежде, чем возникнет перерегулирование по theta.

### alt_control_demo.py — внешний контур по высоте

```
h_ref ──► h_err = h_ref - h_meas
              │
              ▼
         alpha_trim + KH * h_err   (KH = 0.006 рад/м)
              │
         clip(±15°)
              │
              ▼ theta_ref
         ┌──────────────────────────┐
         │  Каскадный ПИД тангажа  │
         │  (тот же, что выше)     │──► delta_e
         └──────────────────────────┘

throttle = trim_throttle = const
```

При 50 м ошибки: `theta_ref = 1.92° + 0.006 * 50 * (180/π) ≈ 1.92° + 17.2°` → клипируется до 15°.  
Контур выходит на насыщение при любом шаге > 23 м. Это нормально — ограничение по тангажу предотвращает срыв.

## 3. Сценарий срыва (demo_control.py)

```
Фаза 1 (0–8 с):   theta_ref = 1.92°, throttle = 0.398  →  тримовый полёт
Фаза 2 (8–25 с):  theta_ref = 20°,   throttle = 0.0    →  срыв
Фаза 3 (25–55 с): theta_ref = −5°,   throttle = 0.398  →  вывод из срыва
```

**Почему throttle = 0 для вызова срыва?**

Модель тяги: `T = 0.5·ρ·S_prop·C_prop·((k_motor·δt)² − Va²)`

При δt = 0 и Va = 20 м/с: T = −0.5·1.27·0.20·1.0·400 ≈ **−51 Н** (пропеллер тормозит!)  
Скорость падает. Требуемый CL = 2mg/(ρ·Va²·S) растёт как 1/Va².  
При Va ≈ 14 м/с CL_req ≈ CL_max (≈ 1.9) → **аэродинамический срыв**.

После срыва (Va = 14 м/с) CL обрушивается с 1.9 до 0.37 (плоская пластина при α ≈ 27°).  
ЛА падает с θ = 20° и α = 44°+ — классический глубокий срыв.

**Вывод (фаза 3):**  
θ_ref = −5° + газ восстановлен → нос вниз → Va растёт → CL восстанавливается → нормальный полёт.

## 4. Почему появляются колебания

Два независимых механизма:

**1. Недостаточное затухание ПИД при падении скорости**  
Момент от руля: `M = ½·ρ·Va²·S·c·Cmde·δe`  
При Va: 30 → 14 м/с эффективность руля падает в **4.6 раза**.  
ПИД настроен на Va = 30 м/с → при 14 м/с контур значительно недодемпфирован → автоколебания.

**2. Насыщение руля в глубоком срыве**  
При α = 50°: Cm = Cm0 + Cma·α = −0.023 + (−0.38)·0.873 ≈ **−0.35** (сильный пикирующий момент).  
Для баланса нужно `δe = 0.35 / 0.5 = 0.70 рад = 40°`. Ограничитель: ±25°.  
Контроллер в насыщении → частичная компенсация → колебания theta → колебания alpha.

## 5. Параметры ПИД — смысл и настройка

### PitchControlParams (control/controllers.py)

Известный дефект: нет упреждающего δe_trim — q-контур стартует с δe = 0, ЛА
проседает ~7 м в первые ~15 с (см. CLAUDE.md, «Открытые дефекты»).

| Параметр | Значение | Смысл | Изменить если... |
|----------|----------|-------|-----------------|
| `theta_Kp` | 1.5 | Скорость реакции по theta | Медленный ответ → увеличить |
| `theta_Ki` | 0.1 | Устранение статической ошибки | Есть остаток → увеличить |
| `theta_Kd` | 0.3 | Демпфирование перерегулирования | Большой первый пик → увеличить |
| `theta_tau` | 0.1 | Постоянная фильтра d/dt (с) | Много шума → увеличить |
| `q_Kp` | 0.5 | Жёсткость q-контура | Вялый ответ на q → увеличить |
| `q_max` | ±60°/с | Ограничение угловой скорости | Слишком резкий манёвр → уменьшить |

### KH (alt_control_demo.py)

`KH = 0.006 рад/м` — усиление контура h → theta.  
- Слишком мало (< 0.003): медленный набор, большой установившийся error.  
- Слишком много (> 0.015): перерегулирование, возможная нестабильность.

## 7. SpeedController — контур воздушной скорости (добавлен в С6)

```
Va_ref (уставка, м/с)
    │
    ▼  error_Va = Va_ref − Va_meas
[PID_Va]  →  delta_throttle   (Va_Kp=0.25, Va_Ki=0.05, Va_Kd=0.01)
    │
    ▼  throttle = trim_throttle + delta_throttle
[saturation 0..1]  →  команда тяги
```

**Ключевое отличие от С5**: в С5 газ = const = trim_throttle, поэтому Va дрейфует
при наборе/снижении (±3.8 м/с). В С6 SpeedController удерживает Va в пределах ±0.6 м/с.

**Параметры** (`SpeedControlParams`):

| Параметр | Значение | Смысл |
|----------|----------|-------|
| `Va_Kp` | 0.25 | Пропорциональный: 1 м/с ошибки → 0.25 коррекции газа |
| `Va_Ki` | 0.05 | Интегральный: убирает статическое смещение |
| `Va_Kd` | 0.01 | Дифференциальный (слабый) |
| `Va_tau` | 0.5 с | Фильтр производной |
| `Va_integral_limit` | 0.5 | Ограничение интеграла |

**Совместное использование с PitchController** (сценарии С6, С7):

```python
# PitchController отвечает за delta_e
ctrl_out = controller.step(t, meas, cfg.dt)
delta_e  = ctrl_out[0]          # руль высоты — от контура тангажа

# SpeedController отвечает за throttle (независимо)
throttle = spd_ctrl.step(Va_meas, cfg.dt)

return np.array([delta_e, throttle])
```

## 9. Боковая САУ — `LateralController` (Этап 3, блок Б3)

Метод — последовательное замыкание контуров (B&M гл. 6). Реализация —
`control/controllers.py`, общая обвязка сценариев — `scenarios/lateral_common.py`.

> **С 2026-10-08 контуры крена и курса устроены иначе** — по схеме PX4/ArduPilot
> (угол → скорость крена → элероны с упреждением; курс — П-контур через atan),
> см. раздел 11.4 и РЕШ-22. Ниже — исходная структура Б3 (исторически).

### 9.1 Структура

```
chi_ref (уставка путевого угла)
   │   e_chi = wrap(chi_ref − chi_meas)        chi_meas — GPS (по земной скорости)
   ▼
[ПИ chi]  ──► phi_ref,  ограничение ±30°
   │   e_phi = phi_ref − phi_meas               phi_meas — ИНС, p_meas — гироскоп
   ▼
[ПИ phi] − Kd_phi·p_meas  ──► delta_a,  ограничение ±25°

beta_meas (зонд УС)
   ▼
[ПИ beta] со знаком «−»  ──► delta_r,  ограничение ±25°   (удержание β = 0)
```

- Рассогласование по курсу приводится к [−π, π) (`wrap_angle`) — разворот по
  кратчайшему пути (170° → −170° — вправо на 20°, а не влево на 340°).
- Демпфирование крена — по измеренной p (гироскоп), а не по производной ошибки:
  нет выброса при скачке уставки.
- Знак руля направления: β > 0 (поток справа) → нос нужно довернуть вправо →
  δr < 0 (δr > 0 — нос влево).
- Удерживается **путевой угол χ** (GPS), а не курс ψ: при боковом ветре САУ сама
  выставляет угол упреждения сноса, линия пути не сносится (С13).
- Продольный канал в боковых сценариях — тот же, что в С6 (`PitchController` +
  `SpeedController` + P-контур высоты), без изменений.

### 9.2 Расчёт коэффициентов (Va = 30 м/с, параметры-аналог)

**Контур крена.** Упрощённая модель (B&M ур. 5.26): `φ/δa = a_φ2 / (s·(s + a_φ1))`,

```
q_dyn = ½ρVa² = 570.7 Па
Cp_p  = Г3·Croll_p  + Г4·Cn_p  = −0.317
Cp_da = Г3·Croll_da + Г4·Cn_da = 0.103
a_φ1 = −q_dyn·S·b·Cp_p·b/(2Va) = 6.63 1/с      (≈ корень апериодики крена −6.73)
a_φ2 =  q_dyn·S·b·Cp_da        = 64.7 1/с²
```

Выбор: ошибка крена 30° даёт полное отклонение элеронов 25°:

```
Kp_phi = δa_max / e_φmax = 25/30            = 0.83
ωn_φ   = √(a_φ2·Kp_phi)                     = 7.3 рад/с
Kd_phi = (2·ζ·ωn_φ − a_φ1) / a_φ2, ζ = 0.9  = 0.10 с
Ki_phi = 0.05 (малый — снимает статическую ошибку крена)
```

**Контур курса.** При координированном развороте `χ̇ = (g/Vg)·tg φ ≈ (g/Vg)·φ`.
Полоса в W = 10 раз уже контура крена:

```
ωn_χ  = ωn_φ / 10                  = 0.73 рад/с
Kp_chi = 2·ζ·ωn_χ·Vg/g,  ζ = 1      = 4.5
Ki_chi = ωn_χ²·Vg/g                 = 1.65
```

Интеграл курса ограничен (`chi_integral_limit = 0.1 рад·с`, вклад ≤ ~9.5° крена) —
против раскачки после больших разворотов, когда φ_ref в насыщении.

**Контур скольжения.** Подобран моделированием (С12) с учётом шума зонда:
`Kp_beta = 0.5`, `Ki_beta = 1.0`. При Kp_beta = 2 шум УС 0.6° даёт дрожание руля
~1.6° на такт при практически том же max |β|.

### 9.3 Параметры (`LateralControlParams`)

| Параметр | Значение | Смысл |
|---|---|---|
| `phi_Kp, phi_Ki, phi_Kd` | 0.83, 0.05, 0.10 | контур крена |
| `chi_Kp, chi_Ki` | 4.5, 1.65 | контур курса |
| `phi_ref_max` | 30° | ограничение уставки крена (радиус ≈ 160 м при 30 м/с) |
| `beta_hold` | True | контур β по зонду; False — δr = 0 |
| `beta_Kp, beta_Ki` | 0.5, 1.0 | контур скольжения |

При изменении скорости полёта или параметров ЛА коэффициенты пересчитать по 9.2
(a_φ1 ∝ Va, a_φ2 ∝ Va², Kp_chi ∝ Vg).

### 9.4 Результаты (моделирование, параметры-аналог)

| Перерегулирование χ | 1.7° | 1.8° |

**С13 — ступенька бокового ветра 5 м/с**, удержание χ = 0°, затем χ = 90°:

| Величина | Моделирование | Треугольник скоростей |
|---|---|---|
| Угол упреждения ψ при χ = 0° | −9.59° | −arcsin(5/30) = −9.59° |
| Путевая скорость при χ = 0° | 29.59 м/с | √(30² − 5²) = 29.59 м/с |

**Вывод о контуре β.** На аналоге Aerosonde контур скольжения по зонду почти
не улучшает координацию: ЛА и без руля направления хорошо координирован
(Cn_β = 0.25, Cn_r = −0.35, Cn_da > 0 — «попутное» рыскание от элеронов).
Пиковое β (~3° в разворотах, 9.5° в момент ступеньки ветра) возникает за доли
секунды — быстрее, чем отрабатывает ПИ-контур. Сильнее эффект проявится на ЛА
со слабой путевой устойчивостью или с неблагоприятным рысканием (Cn_da < 0 —
например, во 2-м издании B&M Cn_da = −0.011). [АВТОР: оценить на своих АДХ.]
Возможное развитие: перекрёстная связь элероны → руль направления (ARI)
как упреждающая добавка к δr.

## 10. Навигация по точкам — `WaypointNavigator` (дорожная карта, блок 4)

Метод — B&M гл. 10–11. Реализация — `control/navigation.py`; подключение —
`FullSAU(nav=...)` (`scenarios/lateral_common.py`), `Game`/`Bench` (3D-игра и стенд).
Навигатор только формирует уставки χ_ref и h_ref для существующих контуров:
`LateralController` (χ → φ → δa) и контура высоты (h → θ → δe) — их коэффициенты
не менялись.

### 10.1 Структура

```
маршрут w_1..w_N (N, E, h)        p = (N, E) — GPS
   │
   ▼
[менеджер маршрута]  прямая w_{i−1}→w_i  /  дуга скругления у w_i  /  кружение у w_N
   │
   ▼
[следование по прямой или окружности]  ──► chi_ref, h_ref  ──► боковая и продольная САУ
```

**Прямая** (B&M 10.1, векторное поле): начало r, орт направления q, χ_q = atan2(q_E, q_N),

```
e_py    = −sin χ_q·(p_N − r_N) + cos χ_q·(p_E − r_E)      (> 0 — правее линии)
chi_ref = χ_q − χ∞·(2/π)·atan(k_path·e_py)
```

Далеко от линии ЛА идёт к ней под углом χ∞, ближе ~1/k_path м — плавно ложится на неё.
Ошибку от ветра (угол упреждения) снимает интеграл контура курса.

**Окружность** (B&M 10.2), центр c, радиус ρ, λ = +1 по часовой / −1 против:

```
d = |p − c|,  ϑ = atan2(p_E − c_E, p_N − c_N)
chi_ref = ϑ + λ·(π/2 + atan(k_orbit·(d − ρ)/ρ))
```

**Менеджер маршрута со скруглением** (B&M 11.2, алгоритм 6). Угол у w_i:
q0 = орт(w_i − w_{i−1}), q1 = орт(w_{i+1} − w_i), ϱ = arccos(−q0·q1):

```
прямая до полуплоскости через z1 = w_i − d·q0 (нормаль q0),   d = R/tg(ϱ/2)
дуга:   c = w_i − (R/sin(ϱ/2))·орт(q0 − q1),  λ = sign(q0_N·q1_E − q0_E·q1_N),
        до полуплоскости через z2 = w_i + d·q1 (нормаль q1)
далее — прямая w_i → w_{i+1}
```

ЛА проходит не через саму точку, а по дуге (срезает угол на R·(1/sin(ϱ/2) − 1)),
зато не проскакивает поворот. Вынос d ограничен половиной соседних участков
(острый угол / короткий участок) — тогда радиус дуги меньше R. Последняя точка
незамкнутого маршрута — прямая до полуплоскости через w_N, затем кружение R_orbit.
Замкнутый маршрут (`loop`) — после последней точки снова к первой.

Высота: на прямой — линейно по ходу участка от h_{i−1} к h_i; на дуге — h_i.

Сначала был реализован вариант без скругления (B&M 11.1, переключение по
полуплоскости-биссектрисе у самой точки): ЛА проскакивает поворот 90° на ~R_min
≈ 160 м и через 15 с всё ещё в ~95 м от новой линии. Поэтому — скругление.

**Правка маршрута в полёте** (`update_route`): цель — точка с тем же номером,
участок к ней — от предыдущей точки нового маршрута (на первом участке — от старта);
кружение остаётся кружением вокруг новой последней точки.

### 10.2 Параметры (`NavParams`)

| Параметр | Значение | Смысл |
|---|---|---|
| `chi_inf` | 60° | угол подхода к линии издалека |
| `k_path` | 0.01 1/м | масштаб перехода на линию ~100 м |
| `k_orbit` | 2.0 | крутизна поля у окружности |
| `R_fillet` | 200 м | радиус скругления углов (0 — без скругления) |
| `R_orbit` | 200 м | радиус кружения у последней точки |
| `orbit_cw` | True | кружение по часовой |
| `loop` | False | замкнутый маршрут |

R_fillet и R_orbit должны быть больше минимального радиуса координированного
разворота по ПУТЕВОЙ скорости: R_min = Vg²/(g·tg φ_max); при Va = 30 м/с, φ_max = 30°
R_min ≈ 160 м в штиль и ≈ 216 м при попутном ветре 5 м/с (Vg = 35 м/с).

### 10.3 Результаты (С14, моделирование, параметры-аналог)

Маршрут: (1000, 0, 100) → (1000, 1000, 130) → (0, 1000, 130) → (600, 300, 100),
старт из (0, 0, 100) на север, затем кружение. Шум датчиков — как в s12/s13.

| Величина | Штиль | Ветер 5 м/с на восток |
|---|---|---|
| \|e_py\| max на прямых (10 с после входа отброшены) | 2.9…3.5 м | 3.3…6.6 м |
| \|e_py\| в конце прямых | 0.2…1.1 м | 0.5…0.9 м |
| \|d − R\| max на дугах R = 200 м | 9.9 м | 36.4 м |
| Кружение R = 200 м: \|d − R\| max / СКО | 10.0 / 1.0 м | 28.0 / 6.9 м |
| Срез угла 90° (мин. расстояние до точки) | 76.5…76.8 м (теория 82.8) | 62.4…73.3 м |
| \|h − h_ref\| в конце участков с изменением высоты | до 8.3 м | до 6.4 м |

При ветре дуги и кружение хуже: на попутном участке Vg = 35 м/с, R_min ≈ 216 м > 200 м —

## 11. Расчёт САУ по модели ЛА — `control/tuning.py` (РЕШ-21)

Все коэффициенты САУ считаются по модели ЛА, а не подбираются: метод
последовательного замыкания контуров (B&M гл. 6). Для другого ЛА или другой
точки настройки:

```python

print_design(d)
PitchController(aircraft, d.pitch); SpeedController(aircraft, d.speed)
LateralController(aircraft, d.lateral); RollHold(aircraft, sp, rng, d.roll); d.KH
```

`python -m control.tuning` печатает расчёт для `AircraftParams()` на 16 м/с.
Умолчания `PitchControlParams`, `SpeedControlParams`, `LateralControlParams`,
`RollControlParams` — результат этого расчёта для FPV-самолёта; `checks/check_sau.py`
сверяет их с расчётом и проверяет переходные процессы на полной модели.

### 11.1 Коэффициенты объекта (`plant_coeffs`, FPV, Va = 16 м/с)

Анти-виндап (условное интегрирование, `PID.unwind`): интеграл скорости крена не
копится, пока элероны в упоре; интеграл высоты — пока θ_ref в упоре. Интеграла

Особенности, найденные при проверке на полной модели (`checks/check_sau.py`) и
в полёте в 3D-тренажёре:

- **Предел q_ref каскада тангажа.** При q_max = 60°/с и Kq = 0.038 руль высоты
  ограничивался Kq·q_max ≈ 2.3° (на 27 м/с с gain scheduling ≈ 0.8°) — ЛА в 3D-полёте
  2026-10-07 «застрял» в наборе на θ = 13.5° и ушёл с 200 на 500 м. Теперь
  q_max = Kθ·40°: при |θc − θ| ≤ 40° каскад тождественен ПД-закону B&M, команду
  ограничивает предел θ_ref.
- **Высота — ПИ.** П-контур имеет статическую ошибку на скорости, отличной от
  точки балансировки (иной α*, иной δe*); ПИ (B&M 6.4.3) её убирает. ζ_h = 1.5: при
  0.9 нуль ПИ давал перерегулирование 18 % на ступеньке 5 м.
- **Крен и курс** — до 2026-10-08 были ПИД крена (ωn_φ = 20, kd = 0) и ПИ курса
  (ωn_χ = 1.05): рывок элеронов в упор при ступеньке курса, перерегулирование 38 %
  на ступеньке 10°, а при kd = 0.2 (стенд) — 67 % и обратный крен −14°. Заменены
  каскадом по схеме PX4 — раздел 11.4.
- **Тангаж.** Модель B&M (α ≡ θ) даёт K_θDC = 0.615; в полной модели θ отрабатывает
  уставку полностью — во внешнем контуре высоты K = 1.
- **Скорость.** Предел интеграла 1/ki (весь диапазон газа) — при 0.5 оставалась
  статическая ошибка 0.13 м/с.
- `PitchController.set_trim_elevator` — упреждающий балансировочный δe; газ по
  высоте `h_Kp` по умолчанию выключен (скорость держит `SpeedController`).

### 11.4 Крен и курс по схеме PX4 / ArduPilot (РЕШ-22)

```
χ_ref, κ ─► χ̇_ref = Vg·κ + K_χ·wrap(χ_ref − χ) ─► φ_ref = atan(Vg·χ̇_ref/g), |φ_ref| ≤ 30°
φ_ref    ─► p_ref = (φ_ref − φ)/τ_φ,  |p_ref| ≤ p_max
p_ref    ─► δa = s·FF·p_ref + s²·(kp_p·e_p + ki_p·∫e_p),  e_p = p_ref − p,  s = Va₀/Va ∈ [0.5, 2]
```

Классы: `RollController` / `RollControlParams` (крен, общий для `LateralController`
и `RollHold`), `LateralControlParams.chi_K`. Аналоги параметров: τ_φ — PX4
`FW_R_TC` (0.5 с), ArduPilot `RLL2SRV_TCONST` (0.45 с); p_max — `FW_R_RMAX`,
`RLL2SRV_RMAX`; FF, kp_p, ki_p — `FW_RR_FF/P/I`, `RLL_RATE_FF/P/I`.

**Расчёт** (`design_sau`). Объект по скорости крена `ṗ = −a_φ1·p + a_φ2·δa`.
- FF = a_φ1/a_φ2: установившаяся p = p_ref без участия обратной связи — упреждение
  делает основную работу (так рекомендуют PX4, ArduPilot, INAV).
- kp_p = (λ_p − a_φ1)/a_φ2: полюс контура p λ_p = 75 рад/с (собственный 56).
- ki_p = kp_p/τ_φ — интеграл по ошибке скорости крена; при p = 0 он интегрирует
  (φ_ref − φ)/τ_φ, поэтому снимает статическую ошибку крена от момента винта.
- Внешний контур: при быстром контуре p φ/φ_ref ≈ 1/(τ_φ s + 1) — апериодический.
- Курс: χ̇ = (g/Vg)·tg φ, а φ_ref = atan(Vg·χ̇_ref/g), поэтому при установившемся
  крене χ̇ = χ̇_ref (тангенс и арктангенс сокращаются). С инерцией крена
  χ/χ_ref = K/(τ_φ s² + s + K), ζ = 1/(2√(K·τ_φ)); ζ = 1 → K_χ = 1/(4τ_φ) = 1.0.
- Масштаб s: a_φ1 ∝ Va, a_φ2 ∝ Va², поэтому FF ∝ 1/Va, kp_p и ki_p ∝ 1/Va².
- κ — кривизна заданной траектории от `WaypointNavigator` (λ/R на дугах и при
  кружении, 0 на прямых): крен atan(Vg²/(g·R)) задаётся упреждением, а не ошибкой
  курса (как центростремительный член L1/NPFG). Без него П-курс отставал на дугах
  (s14, ветер: |d − R| 12.8 м против 4.3 м).

Почему не прежний ПИД: ступенька уставки шла через два П-звена подряд (2.74 и
0.67) — 10° курса давали φ_ref = 27.6° за один шаг и элероны 18.7° (почти упор),
p = 166°/с через 0.05 с. Каскад ограничивает скорость крена (p_max), а уставку
крена формирует плавно: |δa| ≤ 8° на ступеньке 10°.

Проверка на полной модели (датчики без шума, ступеньки курса 10 / 30 / 90°):

| Условия | Перерегулирование | t_уст 5 %, с | φ max, ° | δa max, ° | p max, °/с |
|---|---|---|---|---|---|
| 16 м/с, штиль | 0 / 0 / 0 % | 2.1 / 2.3 / 4.7 | 12.7 / 29.6 / 30.3 | 8.1 / 15.3 / 15.3 | 57 / 109 / 109 |
| 25 м/с, штиль | 0 / 0 / 0 % | 2.1 / 2.9 / 7.0 | 19.7 / 30.1 / 30.1 | 7.1 / 8.9 / 8.9 | 88 / 110 / 110 |
| 12 м/с, штиль | 0 / 0 / 0 % | 2.1 / 2.1 / 3.7 | 9.5 / 27.0 / 30.7 | 8.9 / 22.2 / 22.2 | 43 / 108 / 108 |
| 16 м/с, ветер 5 м/с E | 0 / 0 / 0 % | 2.2 / 2.4 / 5.4 | 12.4 / 29.9 / 30.5 | 7.7 / 14.5 / 14.5 | 74 / 126 / 126 |

Для сравнения прежний регулятор (16 м/с, штиль, kd = 0 / kd = 0.2): ступенька 10° —
перерегулирование 38 % / 67 %, δa max 18.7°, p max 166°/с. В ветре установившаяся

на 0.2–0.3 с, δa max меньше вдвое.

### 11.5 Координация разворота: ограничение скорости φ_ref и микс δa → δr (РЕШ-23)

После перехода на каскад крена на стенде остался рывок носа на входе в разворот.
Причина — обратное рыскание элеронов (Cn_da < 0), а не руль направления: при
δr = 0 рывок тот же. Уставка крена при ступеньке курса прыгала за один шаг,
p_ref сразу упирался в p_max, упреждение давало δa ≈ 15° скачком — нос дёргался
против разворота (r = −34°/с), затем в сторону разворота (+48°/с) за 0.4 с.
Контур β (kp_β = 0.5) отвечает только после роста β и рывок не убирает.

Два средства (оба — штатные в автопилотах):
- **Ограничение скорости уставки крена** `phi_ref_rate` = 90°/с (PX4
  `FW_PN_R_SLEW_MAX`): φ_ref нарастает рампой, δa не скачет. При включении САУ
  ограничитель стартует с текущего крена.
- **Микс элеронов в РН** `da_dr_mix` (ArduPilot `KFF_RDDRMIX`): δr += K·δa. Момент
  рыскания от элеронов гасится сразу, без ожидания β. K = −N_δa/N_δr,
  N = Г4·Croll + Г8·Cn (ṙ, B&M 3.17); для FPV K = −Cn_da/Cn_dr = −0.654.
  При `beta_hold = False` руль направления в нейтрали, микс тоже выключен
  (сохранён смысл варианта «δr = 0» в s12/s13).

Ступенька курса 30° на 16 м/с (полная модель, без шума):

| | рывок носа влево, r min | max \|ṙ\| | β max | t_уст 5 % |
|---|---|---|---|---|
| каскад (р. 11.4) | −34°/с | 498°/с² | 7.2° | 2.3 с |
| + ограничение φ_ref 90°/с | −18 | 244 | 5.8 | 2.5 |
| + микс δa → δr | −12 | 167 | 3.2 | 2.3 |
| оба (по умолчанию) | **−5.6** | **119** | **2.6** | 2.5 |

На 12 и 25 м/с: r min −4.4 / −6.3°/с, β max 4.4 / 1.2°. Cn_da оценён на
крейсерском CL = 0.28 и с ростом CL (малая скорость) растёт по модулю — микс на
малой скорости недокомпенсирует, остаток добирает контур β.

## 12. САУ одним классом — `control/sau.py` (РЕШ-26)

Одна и та же САУ в сценариях s12–s14 (`FullSAU` — обёртка), 3D-тренажёре и стенде
(стенд — подкласс `BenchSAU` с режимом «Срыв»). Раньше она была собрана трижды.

```
state, Va, α, β ─► sensors ─► meas ─► estimator ─► est ─┬─► _guidance: nav → refs.chi, refs.h, refs.kappa (ROUTE)
                                                         └─► _control:
     refs.h, refs.Va / refs.theta ─► lon ─► θ_cmd, δt ─► [prot: защита по α] ─► θ_ref ─► pitch ─► δe
     refs.chi, refs.kappa ─────────► lat: χ → φ_ref → δa;  β → δr
```

| Звено | Сейчас | Интерфейс | Что встанет на его место |
|---|---|---|---|
| `sensors` | `TruthSensors` (игра, стенд), `NoisySensors` (сценарии) | `measure(t, state, Va, α, β) → meas` | частоты, задержки, дрейф гироскопа (блок 5) |
| `estimator` | нет: оценка = измерения | `update(meas, dt) → est` | комплементарный фильтр, EKF |
| `nav` | `WaypointNavigator` | `step(pn, pe, χ) → (χ_ref, h_ref) или None`, `.kappa` | L1 / NPFG, траектории Дубинса |
| `lon` | `TECS` (по умолчанию, раздел 13); `AltSpeedHold` = `AltitudeHold` + `SpeedController` (`lon="split"`, стенд) | `step(refs, est, dt, hold_alt) → (θ_cmd, δt)`, `reset_alt()`, `thr_trim` | — |
| `prot` | `AngleOfAttackProtector` (стенд) или нет | `step(α, θ_cmd, δt*, dt) → AUAOutput` | — |
| `pitch` | `PitchController` | `set_pitch_setpoint`, `step` | тангаж по схеме крена (θ → q_ref → FF + ПИ) с упреждением q в развороте |
| `lat` | `LateralController` (`lat.roll` — `RollController`) | `set_course(χ, κ)`, `step(meas, dt)` | INDI по крену — вместо `lat.roll` |
| весь `_control` | каскад | подкласс `SAU` | LQR / LQI, INDI, NMPC — для сравнения с каскадом |

Режимы `Mode`: `PITCH` (θ_ref + курс), `ALTITUDE` (h_ref + курс), `ROUTE`
(курс и высота от навигатора). Скорость держится во всех режимах. Взлёт, посадка,
кружение, возврат домой — новые значения `Mode` и ветки в `_guidance` / `_outer`.

- `engage(θ, h, Va, χ)` — включение: уставки равны текущему режиму, интегралы с нуля.
- `set_mode(m)` — смена режима: интеграл высоты с нуля; при переходе в `PITCH`
  уставка тангажа подхватывает последнюю команду внешнего контура (без скачка).
- `fly_route(точки, старт)` — маршрут с первой точки, режим `ROUTE`.
- `refs.hdot` — упреждение темпа высоты (в `ROUTE` — от уклона участка навигатора).
- Последний шаг для журнала и окна стенда: `est`, `theta_cmd` (до защиты),
  `theta_ref` (после), `prot_out`, `controls`.

Привод рулей — часть объекта управления, а не САУ: его место в `sim/` (между
командой и рулём в `derivatives` или в шаге интегрирования). Это решение автора.

**Проверка перехода:** s12–s14 — текстовый вывод и все массивы .flightlog
совпали с прежними до бита. Игра и стенд — прежний код против `SAU` на истинных
измерениях: 120 с со всеми режимами, ступеньками, маршрутом, защитой по α и
«Срывом» — расхождение управлений и состояния 0.0.

## 13. TECS — управление полной энергией (`control/tecs.py`, РЕШ-27)

Продольный внешний контур САУ по умолчанию (`SAUParams.lon = "tecs"`): s12–s14,
3D-тренажёр. Стенд — раздельные контуры (`lon = "split"`): блок-схемы окна под них.
Схема — Lambregts (1983), так же устроены PX4 (`FW_T_*`) и ArduPilot (`TECS_*`).

### 13.1 Уравнения

Темпы энергии на единицу веса и скорости (безразмерные, рад), γ = ḣ/Va:
```
Ė = γ + V̇/g                    — полная энергия E = h + V²/2g      ← газ
Ḃ = w·γ − (2 − w)·V̇/g          — баланс высоты и скорости, w = 1   ← тангаж
```
Из m·V̇ = T − D − m·g·sin γ: **Ė = (T − D)/(m·g)** — от тангажа не зависит;
**Ḃ = 2γ − (2 − w)·Ė** — тангаж меняет γ, ∂Ḃ/∂θ ≈ 2.

```
ḣ_ref = ḣ_ff + K_h·(h_ref − h),   −Va·γ_sink(Va) ≤ ḣ_ref ≤ Va·γ_climb(Va),   γ_ref = ḣ_ref/Va
V̇_ref = K_V·(V_ref − Va),          |V̇_ref| ≤ acc_max
δt = δt*(V_ref) + K_E·Ė_ref + ki_T·∫(Ė_ref − Ė)
θ  = α*(Va) + γ_ff + ki_B·∫(Ḃ_ref − Ḃ),          γ_ff = (Ḃ_ref + (2 − w)·Ė_ref)/2
```
- δt*(V), α*(V) — балансировка горизонтального полёта, таблица по скорости
  (10…28 м/с): упреждение на любой скорости (раньше δt* был один, на 16 м/с).
- ḣ_ff — уклон участка маршрута × путевая скорость вдоль него (навигатор,
  `h_slope`); без него на наклонной прямой отставание ḣ_ff/K_h ≈ 1 м.
- V̇ — производная отфильтрованной Va (τ_f = 0.15 с), ḣ — вертикальная скорость GPS.
- Режим PITCH: γ_ref = γ — газ держит скорость, тангаж задан.
- Защита от потери скорости: при Va < Va_min = 1.25·Va_stall = 9.4 м/с вес высоты
  w → 0 (тангаж держит только скорость), набор запрещён, газ → 1 (полностью — на 1.5 м/с ниже).
- Анти-виндап обоих интегралов (условное интегрирование).

### 13.2 Расчёт (`design_sau` → `d.tecs`, FPV, 16 м/с)

| Величина | Формула | Значение |
|---|---|---|
| K_h, K_V | требование (как ω_h раздельных контуров) | 0.5 1/с |
| K_E = ∂δt/∂Ė | g/a_V2 | 0.852 |
| ki_T | ω_T·K_E, ω_T = 2 рад/с | 1.703 |
| ki_B | ω_B/2, ω_B = 2 рад/с | 1.0 |
| γ_climb(V) | 0.7·min(Ė_max(V), sin 15°) | 10.4° (на 28 м/с 8.1°) → ḣ 1.8…4.5 м/с |
| γ_sink(V) | 0.7·min(−Ė_min(V), sin 15°), Ė_min — газ 0 | 4.9° на 10 м/с … 10.4° с 19 м/с → ḣ 0.9…9 м/с |
| acc_max | 0.7·(T(1) − D)/m | 5.4 м/с² |

Внутренние контуры — чистые И: объект (a_V2/g)/(τ_f s + 1), L = ω_T/(s(τ_f s + 1)),
срез ω_T, запас по фазе 90° − atan(ω_T·τ_f) = 73°. П-часть (PX4 `FW_T_THR_DAMP`)
не берём: шум ПВД 0.2 м/с проходит через дифференцирование V̇ с усилением
ω_T·K_E·σ_V/g, которое от τ_f не зависит (σ газа 0.049 с П-частью, 0.019 без неё).
Интеграл V̇ — сама отфильтрованная Va, почти без шума. Точнее было бы брать Ė
с акселерометра (продольная перегрузка — это и есть (T − D)/(m·g)) — звено estimator.

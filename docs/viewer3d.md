# 3D-тренажёр (`viz/viewer3d.py`)

3D-проигрыватель полётных логов `.flightlog` на движке Ursina (Panda3D).
Решение о зависимости — РЕШ-16 (`docs/decisions.md`). Модуль только отображает:
физику и САУ не импортирует, читает файл через `flight_logger.load_log()`.

Статус (2026-10-06): блок 1 — проигрывание логов ✅; блок 2 — пилотирование
в реальном времени `scenarios/GameScenario3D.py` ✅ (раздел 8).

---

## 1. Установка и запуск

```bash
pip install ursina                       # один раз; тянет panda3d

python viz/viewer3d.py                   # последний .flightlog из results/
python viz/viewer3d.py results/<файл>.flightlog
python viz/viewer3d.py <файл> --speed 2 --cam 3 --at 20
python viz/viewer3d.py <файл> --at 22 --cam 1 --shot out.png   # скриншот и выход
```

| Ключ | Назначение |
|---|---|
| `path` | файл `.flightlog`; без него — самый свежий в `results/` |
| `--speed` | скорость проигрывания (по умолчанию 1 — реальное время) |
| `--cam 1..4` | камера на старте |
| `--at T` | начать с момента T, с |
| `--shot файл.png` | отрисовать ~40 кадров, сохранить скриншот, выйти (для отчётов и проверок) |
| `--map default` | карта мира (раздел 9) |

Из кода: `from viz.viewer3d import play; play(path, speed=1.0, cam=1)`.

Лог создаётся любым сценарием (s1–s10, архивные p7–p10), 3D-тренажёром, стендом
и конструктором — все пишут `.flightlog` через `FlightLogger.save()`. Тот же лог в
2D (графики и анимация) — `python viz/viewer.py файл.flightlog`.

## 3. Что на экране

**Сцена** — мир `viz/world3d.py` (один и тот же для проигрывателя и игры, раздел 9).
- Небо, дымка (линейный туман, в обзоре реже).
- Красный след — пройденный путь; тёмная линия на земле — его проекция;
  белый отвес — от ЛА до земли.

**Модель ЛА** — `viz/aircraft3d.py`, выбирается по типу ЛА из метаданных лога
(`aircraft.name`, реестр `MODELS`; старые логи без имени и неизвестные типы —
модель по умолчанию). Сейчас одна модель — low-poly высокоплан по мотивам
Cessna 172 (та же схема, что у флайт-модели FPV): фюзеляж с остеклением, крыло
NACA 2412 с подкосами, оперение, шасси с обтекателями, двухлопастный винт.
Строится процедурно из сечений (≈ 2 тыс. треугольников, файлов-ассетов нет),
масштабируется до размаха `b` из лога — это внешний вид, не геометрия
флайт-модели. Камера «из кабины» — в точке глаза пилота модели (`model.eye`).
Рули отклоняются по логу на истинные углы:

| Руль | Знак (как в `sim/config.py`) |
|---|---|
| δe > 0 | задняя кромка руля высоты вниз (нос вниз, `Cmde < 0`) |
| δa > 0 | правый элерон вверх, левый вниз (правый крен, `Croll_da > 0`) |
| δr > 0 | задняя кромка руля направления влево (нос влево, `Cn_dr < 0`) |

Винт вращается пропорционально δt.

**HUD** (`viz/hud3d.py`, 2026-10-15): белая символика с мягкой тёмной обводкой в стиле OSD,
без плашек, шрифт Bahnschrift, подписи по-английски.
Сверху — строка режимов (в проигрывателе — `LOG` и название сценария) и курсовая лента:
ψ — галочка, путевой угол χ — ромб, уставка χ_ref — скоба. В центре (камеры 1–2) —
продольная ось ЛА («W»), маркер вектора воздушной скорости и линии тангажа; их
положения — проекция реальных направлений через объектив камеры, поэтому разнос
«ось — маркер» по вертикали равен α, по горизонтали — β. Слева — Va (уставка в
скобках), газ, α, β, φ, χ; справа — лента высоты с уставкой h_ref и вертикальной
скоростью; справа внизу — круг ветра (север вверху, стрелка — куда дует). Рамка
`AOA … WARN / CRIT / STALL` появляется только при α ≥ alpha_warning (канал `alert`
лога); внизу — последнее событие из `meta["events"]`. F1 — уровень HUD: всё →
режимы и предупреждения → пусто. На полосе времени — метки событий.

## 4. Системы координат и ориентация

Симулятор (docs/physics.md): земная СК — x на север, y на восток, h вверх
(D = −h); связанная СК — x вперёд, y на правое крыло, z вниз; углы φ, θ, ψ,
порядок поворотов ZYX.

Ursina — левая СК: X вправо, Y вверх, Z вперёд. Отображение:

```
(N, E, D)  ->  (X, Y, Z) = (E, −D, N)
```

При нём восток справа от севера, как на карте, — разворот вправо (ψ растёт)
и на экране идёт вправо, зеркальности нет.

Ориентация силуэта задаётся не углами Эйлера Ursina, а двумя векторами из
матрицы R_b→n = Rz(ψ)·Ry(θ)·Rx(φ):

```
нос  x_b = [cθ·cψ,  cθ·sψ,  −sθ]                       (1-й столбец)
низ  z_b = [cφ·sθ·cψ + sφ·sψ,  cφ·sθ·sψ − sφ·cψ,  cφ·cθ] (3-й столбец)
верх = −z_b
```

Оба переводятся в СК Ursina и передаются в Panda3D `lookAt(нос, верх)`.
Так исключена путаница порядка поворотов и знаков углов движка.

Положение интерполируется линейно между отсчётами лога (плавность на 60+ кадр/с);
углы и рули берутся по ближайшему отсчёту (при dt = 0.01 с этого достаточно).

## 7. Ограничения

- В проигрывателе логов ЛА может пролететь «сквозь» холм (он только рисует лог).
  В игре и на стенде земля твёрдая (раздел 8, «Земля и посадка»); здания и
  деревья — нет.
- Вектор воздушной скорости не рисуется — α и β видны только по приборам и по
  расхождению носа со следом (стрелка потока — возможное улучшение).
- Ursina — только в `viz/viewer3d.py`; остальной проект по-прежнему numpy + matplotlib.

## 8. Пилотирование в реальном времени (`scenarios/GameScenario3D.py`)

```bash
python scenarios/GameScenario3D.py                          # штиль, h0 = 100 м
python scenarios/GameScenario3D.py --wind-n -5 --wind-e 3   # ветер на север / восток, м/с
python scenarios/GameScenario3D.py --turb moderate          # турбулентность Драйдена (physics.md 4.5)
python scenarios/GameScenario3D.py --sensors truth          # САУ на истинных значениях (без датчиков и EKF)
python scenarios/GameScenario3D.py --est none               # реалистичные датчики без оценивателя
python scenarios/GameScenario3D.py --ap --cam 3 --h0 200    # старт с САУ, камера, высота
```

Физика — та же 6DOF-модель: `step_rk4`, dt = 0.01 с, управление заморожено на шаг.
В каждом кадре выполняется столько шагов, сколько прошло реального времени
(не больше 10 за кадр — при просадке кадров игра замедляется, а не «прыгает»).
Старт — балансировочный горизонтальный полёт над ВПП карты, Va = 16 м/с, курсом
вдоль полосы (`World.start_psi`: default — 0°, север).

**Ручной режим** — рули отклоняются, пока клавиша нажата, и возвращаются к
балансировке со скоростью 20°/с (как ручка RC-пульта):

| Клавиша | Действие | Отклонение |
|---|---|---|
| W / S | руль высоты: нос вниз / вверх | δe = δe_трим ± 2° |
| A / D | элероны: крен влево / вправо | δa = ∓3° / ±3° |
| Q / E | руль направления: нос влево / вправо | δr = +3° / −3° |
| Shift + W/S/A/D/Q/E | большие расходы | δe, δa, δr = ±10° |
| ↑ / ↓ | триммер руля высоты (↑ — нос вниз) | ±0.3° за нажатие |
| X / Z | тяга | ±5 % за нажатие |

Двойные расходы (dual rate, как на RC-пульте): клавиша даёт только «нажато / отпущено»,
поэтому обычные отклонения малы — для точного пилотирования, а Shift включает большие —
для энергичного маневра (выравнивание на посадке, вывод из сваливания). Отклик FPV в
разомкнутом контуре (моделирование, Va = 16 м/с, руль удерживается 1 с, штиль):

| Отклонение | Отклик |
|---|---|
| δe 2° / 10° (нос вверх) | q ≈ 21 / 106 °/с; α через 1 с ≈ 2.1 / 8.5° |
| δa 3° / 10° | p ≈ 29 / 100 °/с |
| δr 3° / 10° | r ≈ 13 / 44 °/с |

δe 10° на 16 м/с выводит α почти на порог предупреждения (9°); δe 15° — уже срыв.

**САУ** (P — вкл/выкл; при включении захватываются текущие θ, Va, путевой угол χ):

| Клавиша | Действие |
|---|---|
| W / S | θ_ref ∓1° (в режиме H — h_ref ∓10 м) |
| A / D | χ_ref ∓10° |
| X / Z | Va_ref ±1 м/с |
| H | удержание высоты (захват текущей) |

САУ — `control/sau.py`, тот же класс, что в s8–s10 (docs/control.md, «Обзор»):
высота и скорость — TECS, тангаж — каскад θ → q → δe, боковой канал — χ → φ_ref → δa,
β → δr. По умолчанию САУ получает реалистичные датчики (`RealisticSensors`: частоты,
запаздывание GPS, дрейф, [SENSORS.md, раздел 7](SENSORS.md)) через оценку состояния —
инерциальный EKF ([control.md, 9.3](control.md)); `--est none` — сырые измерения без
оценки, `--sensors truth` — истинные значения (`TruthSensors`). Датчики и
оценка работают и в ручном полёте. Старт — в балансировке относительно воздуха (с ветром
нет скачка скольжения).

Общие клавиши: T — турбулентность (выкл → слабая → умеренная; включается с текущего
момента, событие в журнале), Пробел — пауза, R — сброс, 1–4 — камера, M — масштаб,
Esc — выход. То же — в стенде и конструкторе (`--turb`, `--turb-alt`, клавиша T).

**Земля и посадка** (2026-10-08, РЕШ-25). Земля твёрдая на всех картах:
поверхность `World.surface()` — ровно нарисованная сетка рельефа + ВПП, перрон,
дорога (+ мост), вода; физика контакта — `sim/ground.py` (docs/physics.md 4.6).
ЛА садится на трёхопорное шасси, катится, Q/E поворачивают носовое колесо,
газом — разбег и взлёт (отрыв ≈ 13 м/с, разбег ≈ 10 м на полном газе). На HUD —
«ON GROUND». Событие «касание v м/с» пишется в лог. Авария (полёт останавливается,
R — сброс): «УДАР О ЗЕМЛЮ» — касание винтом, крылом, хвостом, днищем;
«ПОЛОМКА ШАССИ» — касание колесом быстрее 3 м/с; «ПРИВОДНЕНИЕ» — касание воды
(карта default). На крутом развороте при рулении (> ≈ 0.6 g) ЛА опрокидывается
на законцовку — узкая колея. Тормозов нет. Масштаб силуэта M (×10) — колёса
визуально уходят в землю, физика — в натуральную величину.
Земля включается в шаг, только когда ЛА ниже ≈ 3 м над поверхностью
(`sim.ground.near_ground`): шаг на земле ≈ 2 мс против 0.35 мс в воздухе.

**Запись**: каждый полёт (до R или до выхода) сохраняется отдельным файлом
`results/Sim_Игра_3D_*.flightlog` (если длился > 2 с) с событиями «САУ вкл/выкл»,
«удержание h», «касание», аварии; время в каждом файле начинается с 0 и монотонно.
Два сохранения в одну секунду не затирают друг друга (суффикс `_2`, `_3`, … —
`flight_logger._auto_path`). Пересмотр — `python viz/viewer3d.py`.
**Углы Эйлера после каждого шага приводятся к каноническому виду** — `sim.state.canonical_euler`:
φ, ψ ∈ [−180°, 180°), θ ∈ [−90°, 90°], через тождество поворота (φ, θ, ψ) ≡ (φ+180°, 180°−θ, ψ+180°);
u, v, w, p, q, r не меняются. Без этого после пилотажа углы копились (найдено 2026-10-06: θ = 3580°
после ~10 кувырков), и включённая САУ «отматывала» обороты — δe в упоре, непрерывные внешние петли.
Проверено: тождество — до 1e-14; повтор пилотажа автора рулями из лога (60–120 с) с нормализацией
и без — траектории совпадают до 6e-11 м; включение САУ из состояния на 250.5 с того же полёта:
без нормализации δe в упоре 5.4 с и |q| ≈ 63°/с непрерывно, с нормализацией — горизонт, δe не в упоре.
Сценарии s1–s9, p7–p10 нормализацию не используют (там углы не выходят за диапазон).
В ручном режиме рули и триммер ограничены упорами ЛА (±25°).

**Местность** — мир из раздела 9: карта 10×10 км, за краем — бесконечная равнина.
Касание рельефа (холм 150 м, берега) — столкновение: проверено, курс на холм
на высоте 100 м под САУ → «столкновение» на склоне, h = рельеф = 90.5 м.

**Проверено (2026-10-06, программные нажатия клавиш)**:

| Действие | Результат |
|---|---|
| без нажатий 1 с | φ = 0, h = 100.0 — баланс |
| D 1 с, затем A 1 с | φ = +29° → +13° → ≈ 4° |
| S 1 с | h 97.6 → 107.8 м за 3 с, Va 29.6 → 28.2 |
| САУ, χ_ref +90° | χ 21° → 111° за < 10 с, φ → 0 |
| то же, боковой ветер 5 м/с на восток | χ = 113.3° (удержан), ψ = 117.4° (снос в ветер), β ≈ 0 |
| удержание h, h_ref +50 м | 154 → 202.8 м за 20 с (статическая ошибка П-закона ~1–2 м) |
| производительность | 71–75 кадр/с, симуляция/реальное время = 1.00 |

**Ограничения**:
- Коэффициенты САУ рассчитаны на крейсер 16 м/с (docs/control.md, раздел 2); вдали от
  него качество падает (масштаб по скорости — только у руля высоты и элеронов).
- Шум датчиков и ветер с порывами в игре не включены (ветер — только постоянный).

## 9. Мир (`viz/world3d.py`), карта `default`

(0, h0, 0) над ВПП, курс на север.

**Карта 10 × 10 км** (X ∈ [−5, 5] км, Z ∈ [−2.5, 7.5] км):

| Дорога | ВПП → деревня | 8 м, мост через реку (настил +1.5 м) |
| Холм | (3.0, 5.2) км + отрог (3.6, 4.5) | 150 м и 80 м, скальная вершина (> 85 м), лес на склонах |
| Леса | склоны холма, вдоль реки (севернее 3 км), северо-запад, роща у деревни, у (1.2, 6.6) км | ~10 тыс. елей |
| Поля | остальное | участки ~200 × 160 м, луга у реки, деревни, аэродрома, одиночные деревья |

Линия E = 0 к северу от ВПП свободна от высоких препятствий — по ней летят
s1–s9, p7–p10, их логи проигрываются на той же карте.

**Равнина за краем**: квадрат 2.5 × 2.5 км (поля 250 м, лесополосы, одиночные
деревья, волны ±2.5 м), размноженный сеткой 7 × 7 вокруг ЛА средствами Panda3D
(`instanceTo`: геометрия одна, при полёте ничего не перестраивается).
Квадраты, попадающие на карту, скрыты; край карты плавно (600 м) переходит
в равнину — высота непрерывна. Равнина повторяется с периодом 2.5 км — так задумано.

**Высота** `World.height(X, Z)` — та же функция, по которой построена сетка:
равнина + (холмы + волны 0…13 м) с весом карты, аэродром выровнен, русло и
озеро врезаны. Используется для тени следа и отвеса. Твёрдая земля физики —
`World.surface()` (по узлам той же сетки, раздел 8 «Земля и посадка»).

Построение мира — ≈ 2.5 с при запуске; частота кадров в игре ≈ 76 кадр/с.
Ближняя плоскость отсечения камеры 0.3 м: при обзоре с 10+ км вода может
«рябить» (точность буфера глубины), на рабочих высотах — нет.

## 10. Испытательный стенд САУ (`scenarios/Bench3D.py`)

Учебный стенд: 3D-полёт в реальном времени + отдельное окно с блок-схемой САУ,
параметры которой меняются ползунками на лету — эффект виден сразу в 3D и на
осциллографе.

```bash
python scenarios/Bench3D.py                       # штиль, h0 = 200 м
python scenarios/Bench3D.py --wind-e 5
```

**Два окна, два процесса.** 3D-окно (слева) — класс `Game` из `GameScenario3D`
(наследник `Bench`): физика, САУ, клавиши. Окно схемы (справа) — `viz/bench_panel.py`,
отдельный процесс на tkinter (стандартная библиотека): рисует схему и осциллограф,
шлёт параметры. Связь — две `multiprocessing.Queue` (параметры → 3D, сигналы → окно,
≈ один пакет за кадр). Очереди ограничены и не блокируют: если окно схемы не успевает
или закрыто, 3D не тормозит. Если 3D-процесс завершился, окно схемы закрывается само.
Окно схемы `control/` и `sim/` не импортирует — перевод градусов в радианы и запись
в регуляторы делает `Bench3D.apply_params()`.

**Схема (канал крена, `LateralController`):**
χ_ref → Σ → [ПИ курса] → [огр. ±φ_max] → Σ → [ПИ крена] → Σ(−Kd·p) → [огр. ±δa_max] → ЛА,
обратные связи χ (GPS), φ (ИНС), p (гироскоп). Ползунки: Kp, Ki курса; ±φ_max; Kp, Ki
крена; Kd; ±δa_max. По умолчанию — штатные `LateralControlParams` (летает).
Ограничение δa меняется только в копии параметров ЛА у САУ, модель ЛА не трогается.
Интегралы при смене параметров не сбрасываются.

Окно схемы: живые значения на стрелках, кнопки ступенек χ_ref (±10°, ±30°, ±90°),
«Параметры по умолчанию», осциллограф 20 с (χ_ref/χ, φ_ref/φ, δa).
3D-окно: стенд стартует с САУ и удержанием высоты; A/D — χ_ref ∓10°, W/S — h_ref,
X/Z — Va_ref, P — САУ вкл/выкл (выкл — контур разомкнут, ручное управление).

**Проверено (2026-10-06)** — ступенька χ_ref +30°, штиль, тот же код САУ без окон:

| Параметры | Перерег. χ | Вход в 5 % | φ max | через 20 с |
|---|---|---|---|---|
| штатные | 6 % | 5.2 с | 31° | φ = 0 |
| Kd = 0 | — | не входит | 45° | колебания φ ±28°, δa в упорах ±25° |
| Kd = 0, Kp_φ = 0.63 | 5 % | 5.0 с | 43° | φ = 0 |
| Kp_χ = 10 | 4 % | 3.3 с | 31° | φ = 0 |
| Ki_χ = 0 | 0 % | 3.5 с | 31° | φ = 0 |
| φ_max = 10° | 6 % | 11.4 с | 10.5° | φ = 0 |

Причина незатухающих колебаний при Kd = 0 (насыщение δa, связь с боковым движением)
не исследовалась. Живой прогон: ползунок Kp крена, сдвинутый вручную, применяется
сразу (колебания при Kd = 0 прекратились при Kp 0.83 → 0.63).

**Ограничения:** просадка ~10 м в первые ~15 с (нет упреждающего δe_trim в
`PitchController`); полёты стенда пишутся в `.flightlog` под именем «Игра 3D».

### 10.1. Вкладки окна схемы (2026-10-06)

| Вкладка | Схема | Ползунки | Воздействия |
|---|---|---|---|
| Крен | χ → ПИ → огр. φ_ref → ПИ − Kd·p → огр. δa | Kp, Ki курса; ±φ_max; Kp, Ki, Kd крена; ±δa_max | ступеньки χ_ref, толчок δa 5° 1 с |
| Тангаж / высота | h → KH (+α_трим, ±20°) → θ_ref → ПИД θ → огр. q_ref → ПИД q → ×−(Va₀/Va)² → огр. δe | KH; Kp, Ki, Kd θ; ±q_max; Kp, Ki, Kd q; флажок GS; ±δe_max | ступеньки h_ref ±10/±50 м, толчок δe 3° 1 с |
| Скорость | Va → ПИД + δt_трим → огр. 0…1 | Kp, Ki, Kd | ступеньки Va_ref ±1/±5 м/с |
| Рыскание (β) | β = 0 → ПИ → ×−1 → огр. δr | вкл/выкл контура; Kp, Ki; ±δr_max | ступеньки χ_ref (разворот рождает β), толчок δr 5° 1 с |
| Защита по α | автомат НОРМ / ПРЕД / КРИТ / ВОССТ между контуром высоты и ПИД тангажа | вкл/выкл; α_пред, α_крит, α_выход; Δθ_пред, θ_восст, δt_восст | «Срыв» (δt = 0, θ_ref = +15°), «Отмена срыва» |
| Навигация | маршрут → менеджер маршрута → следование по прямой / окружности → χ_ref, h_ref → вкладки «Крен», «Тангаж» | R скругления, R кружения, направление кружения; χ∞, k_path, k_orbit | «Лететь по маршруту», «Стоп»; точки — в окне станции (раздел 11) |

Толчок — добавка к команде САУ на входе ЛА на 1 с (возмущение, которое контур
должен отработать). Ступеньки и толчки работают только с включённой САУ.
`PitchController` хранит последнюю `q_ref` (для схемы), `Game.KH` — атрибут экземпляра.

**Защита по α** — автомат `control/aua.py` (`AngleOfAttackProtector`), отключаемый,
по ИСТИННОМУ α (без шума; сравнение «зонд vs косвенная оценка» сюда не входит).
Вход — θ_ref контура высоты, выход θ_ref* → ПИД тангажа; в КРИТ/ВОССТ тяга
принудительно δt_восст. Штатные пороги — из параметров ЛА (у FPV α_пред 9°, α_крит 12.2°),
выход из восстановления α < 10°, θ_восст −7°, δt_восст 1.0. На вкладке — диаграмма
состояний с подсветкой текущего, шкала α с зонами (норма / пред / крит / срыв по
`alpha_stall`) и нормальная перегрузка n_y = −fz_аэро/(m·g).
Режим «Срыв»: тяга 0, θ_ref = +15°. С защитой режим снимается сам, когда автомат
перехватил управление (КРИТ), — дальше удержание текущей высоты; без защиты — кнопкой.

Проверено на прежнем ЛА (Aerosonde, 30 м/с; тот же `Bench._sau` без окон и живой прогон
с переключением флажка в окне):

| | α max | Va min | Итог |
|---|---|---|---|
| защита вкл | 20.1° | 13.0 м/с | перехват через 3.3–3.5 с после «Срыва», возврат к Va = 30, потеря ~16 м |
| защита выкл | 59° | 9.7 м/с | сваливание, α колеблется 9–59°, земля через ~22 с с 200 м |

Ступеньки штатных контуров (штиль): h_ref +50 м — 90 % за 9.2 с, перерег. 0.3 м
(δe на старте в упоре −25°); Va_ref +5 — 90 % за 2.4 с, остаточная ошибка 0.15 м/с
(интеграл `SpeedController` ограничен ±0.025 тяги, δt_трим посчитан для 30 м/с);
χ_ref +90° — β max 3.1°, δr max 1.9°.

с частотой 10 Гц (`EST_TEL_DT`), ключ `"est"` телеметрии; станция хранит историю 90 с.

Как читать: err filt внутри ±3σ и NEES в зелёной полосе — фильтр честен; err filt систематически
вне 3σ — фильтр самоуверен по этой величине; NIS ≪ 1 — шум измерения R завышен (измерение
почти не используется), NIS ≫ 1 — занижен или модель неверна; отношение > 1 подряд дольше
порогов `lockout_s` / `gps_reset_s` — сброс или коррекция без проверки.

**Проверено (2026-10-17)** — станция без 3D на телеметрии безоконного полёта (выброс GPS
+30 м на 70…76 с: 29 отсчётов отбракованы, видно на AIDING и TEST RATIO HISTORY), ветка
без EKF; живой запуск `GameScenario3D --ap --bench` с EKF, `--est none`, `--sensors truth` —
без ошибок. Стоимость отчёта — ≈ 0.5 мс раз в 0.1 с.

**Связь** — две очереди: окно → 3D `("route", {"wps": [(N, E, h)], "loop"})`,
`("go" | "stop", None)`; 3D → окно — словарь на кадр (`Game._station_telemetry()`):
положение, углы, скорости, рули и команды, уставки, табло режимов (`Game._fma()`),
производные энергии TECS, последние события. Постоянные данные ЛА (пределы рулей,
пороги α, скорости полос) — `station_info()` при запуске. Окно `sim/` и `control/`
не импортирует.

**Фон** — `World.save_top_image(px)` (viz/world3d.py): та же раскраска, что у 3D-сетки,
север вверх, охват map_x × map_z; кэш `viz/map_cache/top_<карта>.png`. default —
цвета клеток сетки + вода (дно русла), дорога, ВПП, перрон, контур деревни. Фон в 4 раза крупнее
окна (масштаб ×4 — 1:1). Окно показывает только карту (не равнину за краем).

**Размер окна** — при запуске номинальный (карта 720 пикс, на стенде 640), но не больше
экрана; окно растягивается мышью. Строка статуса, PFD, правая колонка, кнопки и плашки
карты масштабируются одним коэффициентом UI (шрифты тоже); карта занимает остаток ширины,
её масштаб — целое прореживание фона (наименьший — вся карта в окне).

**Проверено (2026-10-06)** — `Game`/`Bench` без окон, подставные очереди, ветер 3 м/с
на восток, замкнутый треугольник (800, 0, 150) → (800, 800, 180) → (0, 800, 150):
точки проходятся по дугам, два круга за 63 с каждый; правка маршрута на 150 с

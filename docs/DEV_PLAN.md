## Известные дефекты и долги

- `compute_trim` — линейный по CL/Cm (без sigmoid), только горизонтальный полёт;
  боковой трим (δa против момента винта) не считает.
- Срыв в Cm и боковые производные после срыва не моделируются (нет данных).
- `Log.E_kin` считается по скорости без ветра: при ветре это энергия по земной скорости.
- `control/lqr.py` использует scipy (DARE) — исключение из правила «только numpy».
- Мощность в логах — полезная мощность винта T·Va; электрическая потребует, чтобы
  `propeller()` возвращал обороты.
- Числа в docs/scenarios_report.md сняты на прежнем ЛА.
- Физика в углах Эйлера: вырождение при θ = ±90° (блок 1, «Ориентация в физике»).
- EKF не убирает уход GPS-положения (5–8 м, не наблюдаем) и до первого манёвра может
  ошибаться по ориентации до ~2° вдоль вектора магнитного поля (docs/control.md, 9.3).
- EKF самоуверен по положению (найдено вкладкой ESTIMATOR, 2026-10-17; моделирование: FPV,
  16 м/с, ветер 5 м/с, слабая турбулентность, 100 с): σ положения 0.2 м при ошибке
  относительно истины 15 м. Причина — уход GPS не входит в модель фильтра, а R положения
  (2 м)² много больше белого шума отсчёта (0.2 м): NIS GPS-положения ≈ 0.06. Варианты — две
  составляющие ухода GPS в состоянии (марковский процесс; рекомендация) или шум процесса по
  положению. Решение — за автором. Там же: уход GPS 16 м против 5–8 м в docs — перепроверить
  модель ухода (`GaussMarkov`, `gps_pos_drift_sigma`).
- Синтетическое β = 0 почти не используется: NIS ≈ 0.01 при σ = 0.3 рад (умолчание
  EKF2_BETA_NOISE); продольная к полёту составляющая ветра — σ ≈ 0.9 м/с.
